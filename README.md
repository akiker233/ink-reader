# 墨读 · 纯前端 TXT 阅读器

一个不需要后端、不需要登录、数据只留在你自己浏览器里的 TXT 阅读器。
导入即读，关掉页面再回来，位置、字号、配色、书签都还在原处。

> 这是「比特工场 2026 秋招程序组考核题」项目二的实现（文本阅读器）。
> 线上地址：**https://ink-reader.pages.dev**（Cloudflare Pages，静态托管）。
> AI 使用情况与协作过程见 [docs/AI开发记录.md](docs/AI开发记录.md)。

## 一、功能

### 考核要求的最低功能

| 要求 | 实现 |
| --- | --- |
| 打开 / 导入文本 | 点击「导入文件」或把 `.txt` / `.md` **直接拖到窗口里**；支持多选批量导入 |
| 书架增删与选择 | 封面网格，点书封即读；右上角删除（二次确认）；可清空 |
| 字号调节 | 14–34px，滑块 + 快捷键 `+` / `-`，实时生效 |
| 背景色调整 | 5 套配色：宣纸 / 纯白 / 青瓷 / 暮色 / 墨黑（后两套是深色） |
| 护眼模式 | 独立开关，另带**色温**与**亮度**两个细调滑块 |
| 阅读进度保存 | 章序号 + 章内比例，去抖落盘；切标签页 / 关页面时立即落盘；重开回到原处 |

### 进阶部分（本次多做的）

- **Markdown 渲染**：`.md` 文件按 Markdown 读（详见第二节），并可在设置面板里对单本书手动切换「纯文本 / Markdown」；Markdown 书的**目录来源**也能单独选「按 `#` 标题」还是「按正文里的章节写法」（见设计决策 11）。
- **编码自动识别**：UTF-8（含 BOM）/ UTF-16 / GB18030 / GBK / Big5，无需手动选编码。
- **自动识别章节**：内置 5 类章节标题模板（`第X章/回/节/卷/篇/部/集`、`Chapter N`、`N、`、`（N）`、`一、`），按命中数取最优模板生成目录；正文里的 `1.` `2.` 列表项也会命中编号模板，所以行首带 `#` 的命中单独计一份、优先级更高，不会被列表项在数量上压过去。识别不到章节时按段落切成约 12000 字的伪章节，长书也不会卡。
- **目录 / 书签 / 全文检索**三合一面板，检索结果带上下文摘要，点击即跳转，正文内高亮命中词。
- **排版细调**：行距、页宽、字间距、首行缩进、5 种字体（宋 / 黑 / 楷 / 仿宋 / 等宽）。
- **键盘快捷键**：翻章、翻屏、调字号、开面板全都能不用鼠标完成。
- **阅读统计**：每本书累计阅读时长、本次会话速度、预计剩余时间。
- **本地优先**：所有数据存本地（正文 IndexedDB + 元数据 localStorage），不发任何网络请求。
- **移动端适配**：工具条在窄屏收成「目录 + 更多」，安全区（刘海 / 主页横条）留白，触摸设备按滚动方向收起工具条、删除按钮常驻。

### Markdown 语法支持

自研解析器，支持以下语法（`npm run test:md` 有 128 条断言覆盖）：

| 类别 | 语法 |
| --- | --- |
| 块级 | ATX 标题 `#`~`######`、Setext 标题（`===` / `---`）、段落（软换行保留为 `<br>`）、分隔线 `---` |
| 列表 | 无序 `- * +`、有序 `1. 1)`、**嵌套**、**任务列表** `- [x]`、松散 / 紧凑列表的间距差异 |
| 引用 | `>` 引用块，支持嵌套与惰性续行 |
| 代码 | 围栏代码块 ` ``` `（带语言标注）+ **语法着色**、行内代码 `` ` `` |
| 表格 | GFM 表格，支持 `:---` / `:---:` / `---:` 三种对齐 |
| 行内 | `**粗体**`、`*斜体*`、`***粗斜***`、`~~删除线~~`、`==高亮==`、`[链接]()`、`<自动链接>`、裸 URL |
| 扩展 | **脚注** `[^1]` 与回链、**定义列表** `术语\n: 定义` |
| 图片 | 降级为带 🖼 前缀的文字链接（本阅读器不做图片加载） |

**渲染安全**：原文先 `escapeHtml` 再拼装，**不支持内联 HTML**，只输出白名单标签；`javascript:` / `data:` / `vbscript:` / `file:` 伪协议一律丢弃（链接降级成纯文本）。导入含 `<script>`、`<img onerror>` 的文件只会看到字面量文本。

**目录来源**：Markdown 书默认取标题行，层级按「命中最多的那一层」选（`# 书名` + 一堆 `## 小节` 的文档取 `##`），第一个标题之前的内容单独成「前言」。但有些 `.md` 只是把书名和一两个小节写成标题，真正的分章还在正文里 —— 所以设置面板里另给了一个开关，可以关掉「按 `#` 标题切分」，改按正文里的「第X章 / Chapter N」这类写法分章（此时 `#` 降级为正文里的层级标题，但行首带 `#` 又长得像章名的行仍优先当章名，免得被正文里的编号列表抢走分章）。两种口径都识别不到章节时，按 1.2 万字切节。正文和渲染方式都不变，只重算章节边界；切换后进度按全文字符下标重新定位，不会跳章。

### 移动端适配

按宽度和设备能力分头处理，不是简单地把桌面版缩小：

| 问题 | 处理 |
| --- | --- |
| 工具条在窄屏放不下（原来的 9 个按钮会溢出屏幕右边缘） | `≤640px` 只保留 返回 / 上一章 / 下一章 / 目录 / **更多**，其余（书签、加书签、护眼、排版、回顶部）收进点开的菜单；`≤860px` 再收起中间的章节 / 百分比胶囊 |
| 工具条跟着 `mousemove` 显隐，触摸设备上完全失效 | 触摸设备改用**滚动方向**：下滚收起、上滚展开，展开后静置 2.6s 自动收起；鼠标设备保持原来的「指针贴近顶部就显示」。设置面板里另有「工具条常驻」开关 |
| 封面上的删除按钮只在 `:hover` 时出现 | 触摸设备上常驻显示、降到 0.72 透明度，`:active` 时高亮；同时关掉「继续阅读」浮层（手指点封面本身就是打开） |
| 刘海 / 屏幕圆角 / 主页横条压住内容 | `index.html` 开 `viewport-fit=cover`，四个方向的安全区 inset 统一成 `--safe-*` 变量，工具条、底部进度条、书架、抽屉、对话框、提示条各自补上 |
| iOS 聚焦输入框会整页放大 | 触摸设备上把所有输入控件字号提到 16px（含 `.paste-area` 这个用类选择器写的例外） |
| 32–38px 的按钮手指点不准 | `@media (pointer: coarse)` 统一抬到 44px 左右；开关视觉尺寸不动，用透明伪元素把热区撑到 44px |
| 触摸设备上 `:hover` 会「粘住」 | 全站 `:hover` 规则统一包进 `@media (hover: hover)` |
| 下拉到顶触发浏览器整页刷新 | `body` 设 `overscroll-behavior: none`，滚动区设 `contain` |
| 地址栏收起时底部被顶出屏幕 | 高度用 `100dvh`（`@supports` 兜底 `100%`） |

`src/composables/useTouch.js` 做成模块级单例：能靠 CSS 媒体查询判断的一律走 CSS，只有「CSS 表达不了的」才读它 —— 目前只有两处：工具条的显隐策略、书架空状态的文案（触摸设备上没有「拖文件进来」这回事）。

## 二、技术栈

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 框架 | **Vue 3**（`<script setup>` SFC） | 组合式 API 让「阅读会话」这种长生命周期状态好拆；SFC 把模板/样式/逻辑收在一个文件里，改一个组件不用跳三个文件 |
| 构建 | **Vite 6** | 冷启动快；产物配置 `base: './'` 后可以丢到任意子目录（GitHub Pages 项目页、Cloudflare Pages 都能直接用） |
| 状态 | **Pinia 2** | 比 `provide/inject` 更规整：`ui` / `settings` / `shelf` / `reader` 四个 store 各管一件事，组件只读状态、调 action，不互相传回调 |
| 持久化 | **IndexedDB** + **localStorage** | 见下面「为什么分两处存」 |
| 样式 | 原生 CSS + CSS 变量 | 主题随时切换、字号随时缩放，靠的就是把颜色和排版参数都做成 CSS 自定义属性；没有引入 UI 框架，避免为了一个滑块拉进来一整套组件库 |
| Markdown | **自研解析器**（约 920 行） | `marked` / `markdown-it` 都要额外带一个 HTML 清洗库才敢开 `v-html`，两个包加起来比自己写还重，而且出了 XSS 说不清是哪一层漏的。自己写就能保证「先转义、只出白名单标签」这条不变量只有一处实现 |
| 无额外依赖 | — | 运行时依赖只有 `vue` + `pinia`，没有 UI 库、没有工具函数库，全部手写 |

## 三、运行方式

需要 Node.js 18+（开发时用的是 24）。

```bash
npm install      # 安装依赖
npm run dev      # 开发服务器，默认 http://localhost:5173
npm run build    # 构建到 dist/
npm run preview  # 本地预览构建产物，默认 http://localhost:4173
npm run test:md  # Markdown 解析器自测（纯 Node，零依赖）
```

`dist/` 是纯静态文件，用任意静态服务器托管都能跑，不需要 Node 运行时。

### 部署到 Cloudflare Pages

线上部署已就位：**https://ink-reader.pages.dev**，项目名 `ink-reader`，与 GitHub 仓库直连、跟踪 `main` 分支，push 后自动重新部署。要自己从头搭一遍：

1. 把仓库推到 GitHub。
2. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → 连接该仓库。
3. 构建设置：
   - Framework preset：`Vue`（或 `None`）
   - Build command：`npm run build`
   - Build output directory：`dist`
4. 保存后自动构建，之后每次 push 到主分支都会重新部署。

因为 `vite.config.js` 里设了 `base: './'`，不需要额外配置子路径，也不需要 `_redirects`（应用是单页但没有前端路由，只有一个入口）。

## 五、几个设计决定

这一节是给「答辩讲解」用的：为什么这么做，不这么做会怎样。

### 1. 正文用 IndexedDB，元数据用 localStorage

一本几 MB 的 txt 塞进 localStorage 会直接 `QuotaExceededError`（配额通常只有 5MB），而且它**是同步 API**，读写会阻塞主线程，导入一本大书足以让页面卡住几百毫秒。

所以拆开存：

- **正文**（大、只在打开某本书时要）→ IndexedDB，异步入库。
- **元数据**（书名、进度、书签、累计时长；小、书架一渲染就要）→ localStorage，同步读，首屏直接可用。

`utils/idb.js` 里还留了一份内存 Map 兜底：隐私模式下 IndexedDB 可能打不开，此时退化成「本次会话内可读」，其余功能照常。

### 2. 进度存「章序号 + 章内比例」，不存页码

页码会随字号、行距、窗口宽度变，是**不稳定量**；章内比例是相对量，换个屏幕或换套字号重开也能落回同一段附近。

存的是 `{ chapterIndex, ratio }`，实际滚动位置在视图层按比例还原。
换字号时视图还会额外记一个**段落锚点**（当前视口顶部压在哪一段、压进多少像素），重排后按锚点还原，保证「眼睛正在看的那一行」不动 —— 只有比例的话，长段落重排后落点会漂到别的段落去。

### 3. 编码识别按「先验 → 试探 → 兜底」的顺序

1. 有 BOM 就按 BOM 走（UTF-8 / UTF-16LE / UTF-16BE），最可靠。
2. 没有 BOM 时，先扫前若干字节里有没有大量 `0x00`：中文文本里出现空字节基本就是 UTF-16。
3. 再试着**严格解码 UTF-8**（`TextDecoder` 带 `fatal: true`）。简体 GBK 文本绝大多数不是合法 UTF-8，会在这里抛错，于是排除。
4. 依次尝试 **GB18030**（GBK 的超集，中文 Windows 的主要编码）与 **Big5**（繁体）。
5. 全都不行，用非严格 UTF-8 兜底，保证「至少能读」，不直接报错。

之所以不引入 `jschardet` 之类的库：那类库动辄上百 KB，而 txt 阅读器面对的真实场景九成是 UTF-8 或 GBK，上面这套几十行就够了。

### 4. 章节识别用「多模板打分」，而不是写死一个正则

`第X章`、`Chapter 3`、`3、`、`（三）`、`一、` 这些写法都有人用，写死一个必然漏。

做法是准备 5 套模板，各自全文扫一遍数命中数，**取命中数最多的那套**（且至少命中 2 次，避免把只有一处 `第X章` 的书硬切成目录）。数字既认阿拉伯数字也认中文数字。

识别不到章节时退化为「伪章节」：按段落边界每约 12000 字切一段，标题写成 `（续 N/M）`。这样超长单章的书不会一次性渲染几万字导致卡顿。

### 5. 主题变量写在 `document.documentElement` 上

抽屉、确认框都是 `Teleport` 到 `body` 的。如果主题变量只写在 `#app` 根元素上，这些浮层在 DOM 上不属于 `#app` 的子树，**继承不到变量**，会出现「切换成深色后，抽屉还是浅色」的割裂感。

写在 `<html>` 上就没这个问题。

### 6. 护眼滤镜挂在整个应用容器上，不挂在正文滚动容器上

最初把 `filter` 挂在滚动的正文容器上，结果长章节滚动明显发涩：`filter` 会强制浏览器建一层滤镜图层，对「比视口高很多」的滚动容器来说，等于每次重绘都要把整章内容全量栅格化。

改挂到只有一屏大的 `.app` 容器上，滤镜的输入被滚动区裁剪，代价骤降。

另外，`buildSurfaceFilter()` 在没有实际效果时**返回 `none` 而不是 `brightness(1)`** —— 后者同样会建滤镜图层，白白拖慢。

### 7. 浮层用「计数」而不是布尔量来挡快捷键

阅读页要响应 `←` `→` 翻章、空格翻屏，但抽屉打开时这些键当然不该穿透。

如果用一个 `isOpen` 布尔量记录，多个浮层（抽屉 + 确认框 + 提示）叠加时，关掉其中一个就会把状态清成「没有浮层」，快捷键提前恢复。

所以 `ui.modalCount` 是计数，`composables/useModalGuard.js` 在每个浮层开/关时 `+1 / -1`。

顺带一提：`/ C B S E T + -` 这些**面板与外观类**快捷键在浮层打开时仍然生效 —— 这样就能「按 C 看目录 → 按 / 切成检索 → 按 S 调排版」一路按下去，也方便在设置面板里用 `+/-` 实时看字号变化。只有翻章和滚动类快捷键会被浮层挡住。

### 8. 检索高亮是「先转义、再包标签」

`v-html` 有 XSS 风险，而正文是用户导入的任意文本 —— 万一 txt 里写着 `<img onerror=...>` 就会被当成 HTML 执行。

所以渲染段落时先做 HTML 转义，渲染完再把命中的词（用 `escapeRegExp` 逃逸后的正则匹配）包上 `<mark>`。用户文本永远进不了标签位置。

正文里写死的 `==高亮==` 走同一个 `<mark>`，但带 `class="hl"` 和检索命中分开——命中是「临时找到的」，跟原文里作者标的高亮不是一回事，配色上要能各自辨认（命中那抹黄 vs 主题强调色）。它的底色用 `color-mix()` 从主题 `accent` 现算，文字颜色沿用正文色，浅色主题下不会变成浅底浅字。

### 9. Markdown 自己写，而不是引库 + 清洗

`marked` / `markdown-it` 默认都**允许内联 HTML**，直接丢给 `v-html` 就等于把用户文件当脚本执行。要用它们就得再加一层 `DOMPurify`，于是运行时多两个包，而且出了 XSS 你得同时怀疑「解析器漏了」和「清洗规则配错了」两处。

自研的解法规避了整个问题类别：解析过程中**不解析内联 HTML**，原文一律先 `escapeHtml`，输出只由解析器自己拼白名单标签（`<p> <h1>-<h6> <ul> <ol> <li> <blockquote> <pre> <code> <table> <a> <strong> <em> <del> <hr> <sup>` 等）。链接再过一道 `safeUrl()`，只放行 `http/https/mailto/tel`、站内锚点和相对路径，`javascript:` / `data:` / `vbscript:` / `file:` 一律丢成纯文本。

这样「转义」这条不变量在代码里只有一处实现，评审时能直接指出来。代价是语法覆盖度不如成熟库（比如不支持内联 HTML、引用式链接只支持一小部分），对这个阅读器够用。

### 10. 代码着色：主题的「第 5 组色」

前 4 个基础色（背景 / 面板 / 正文 / 强调）能推算出边框、次级文字这些派生色，但**推不出「关键字应该是什么颜色」**——关键字和正文都是深灰就等于没高亮。所以每个主题额外带一组 `code` 色板（代码底、关键字、字符串、注释、数字）。

取值按 WCAG 对比度挑过一遍：关键字 / 字符串 / 数字对代码底色都在 4.7:1 以上（正文级 AA），注释刻意压到 3.8–4.2 之间——它是补充信息，跟代码同等醒目反而干扰阅读，但也不低于 3.8，免得深色主题下糊成一片灰。

### 11. Markdown 书名后的「按扩展名判断 + 可手动改」

导入时按后缀（`.md` / `.markdown` / `.mdx` / `.mdown` / `.mkd` / `.mkdn`）决定 `format` 字段。但这个判断一定会错——有人把 Markdown 存成 `.txt`，也有人把日志存成 `.md`。所以：

- 元数据里存 `format`，只影响**怎么渲染**，正文始终存原文，切换不需要重新导入；
- 设置面板里给了切换开关（阅读页工具条上就能直接打开这个面板），按书生效（不是全局设置），因为它描述的是文件性质而不是阅读偏好；
- 老数据没有 `format` 字段，`bookFormat()` 一律按纯文本处理，不用写迁移。

**分章口径是另一件事，所以做成另一个开关。** `format` 说的是「正文怎么渲染」，`chapterSource` 说的是「目录从哪来」，两者互不派生：一份 `.md`（渲染成标题、列表、代码块）完全可以按正文里的「第X章」分章。

- 取值只有 `'heading'`（默认，取 `#` 标题行）和 `'plain'`（用纯文本那套正则），同样按书存进元数据，同样不需要重新导入；
- 关掉「按 `#` 标题切分」后，`#` 标题不再被当成章节、也不再被 `head` 偏移吃掉，而是作为正文里的层级标题照常渲染 —— 所以看到的是「一级标题 + 章名分章」的组合，不是标题消失；
- 换口径等于换一套章序号，沿用章内比例会跳到别的地方，所以和切渲染方式一样按**全文字符下标**重新定位；
- 老数据没有该字段，`bookChapterSource()` 一律按 `#` 标题处理。
- 目录面板顶部那句「识别规则为「…」」跟着实际口径走，免得切完不知道现在按什么在分。

### 12. 触摸设备的工具条按滚动方向显隐，而不是照搬桌面的 mousemove

桌面版是靠 `mousemove` 的 `clientY` 判断「指针贴近顶部就显示」的。这套逻辑在手机上彻底失效 —— 触摸屏不会产生 `mousemove`（手指划过会派发 `touchmove`），结果是工具条**永远停在初始的显示状态**，再也收不起来，白白占掉顶部的阅读空间。

滚动的语义在手机上正好是反的：往下滚 = 正在读正文（想全屏），往上滚 = 常常是在找导航。所以触摸设备改成按滚动方向处理，展开后再加一个 2.6s 的静置延时自动收起，避免工具条一直挂在那儿。

两个实现细节：位移小于 2px 的方向变化直接忽略（惯性滚动、回弹会抖出 1px 级的反向信号）；程序化跳转（换章、换字号重排）会同步滚动基准值，否则「跳章」本身会被误判成「用户往下滚」而把工具条收掉。

`settings.keepToolbarOpen` 是这条策略的全局旁路 —— 有人就是不喜欢自动隐藏，设置面板里给了开关。

### 13. 移动端细节靠 CSS 媒体查询，JS 只兜「CSS 表达不了」的

`(pointer: coarse)` / `(hover: hover)` 两个媒体查询能覆盖绝大多数移动端差异（点击热区、hover 粘滞、输入框字号），所以这些都写在 CSS 里，`useTouch.js` 只在两处被用到：工具条显隐策略、书架空状态文案。

这样做的理由是**少一处状态就少一处不一致**：如果把「是不是移动端」抽成一个 JS 布尔量然后到处 `v-if`，会同时出现「CSS 认为窄屏、JS 认为非触摸」的中间态，样式和逻辑各说各话。反过来，两处 JS 用法都做成模块级单例而不是每个组件各 `matchMedia` 一次 —— 「这台设备是不是触摸屏」全局只该有一个答案，插拔鼠标、翻转平板时也只需要维护一个监听。

## 七、已知限制

- **Markdown 支持的是常用子集**：不支持内联 HTML（出于安全刻意为之）、不支持引用式链接定义 `[a]: url`、不支持数学公式、图片只降级成文字链接。
- **数据不跨设备同步**。存本地是刻意的设计（隐私 + 零后端），但换个浏览器、清一次站点数据，书架就没了。
- **章节识别是启发式的**，没有目录的非标准排版（比如章节名自带序号但格式很怪）可能识别成伪章节 —— 这时仍能正常阅读，只是目录粒度粗一些。Markdown 书的目录取标题行，层级靠「命中最多的那一层」，如果文档标题层级很乱（比如 `#` 和 `##` 混用且数量相同），可能选到不是你想要的那一层。
- **阅读时长只在页面可见时累加**，后台挂着不计入；这是刻意的，否则挂一夜就成「读书 8 小时」了。
- **移动端的验证是设备模拟，不是真机**：用 Chrome DevTools 的设备模拟（390×844 / 768×1024，DPR 3 / 2，触摸）测的，安全区用注入 `--safe-top: 47px` 这类变量来模拟刘海和主页横条。真机上的浏览器 UI（地址栏收缩动画、iOS 弹性滚动）没有实测过。
- **触摸设备的工具条按滚动方向显隐**：如果一章短到没有滚动量（撑不满一屏），滚动事件根本不触发，此时工具条会保持当前状态。桌面端不受影响。
- 未做 `service worker` 离线缓存。构建产物本身是纯静态的，配合托管平台的缓存已经够用。

## 八、浏览器支持

面向现代浏览器（Chrome / Edge / Firefox / Safari 近两年版本），桌面与移动端均可。

用到了 `IndexedDB`、`TextDecoder`、`color-mix()`、`aspect-ratio`、`:has` 之外的常规 CSS。
隐私模式 / 禁用 IndexedDB 时会降级为内存存储（正文当次会话可读，刷新后需重新导入）。

移动端用到了 `100dvh`、`env(safe-area-inset-*)`（配合 `viewport-fit=cover`）、`@media (pointer: coarse)` / `(hover: hover)`。
前两项都有兜底：不认 `dvh` 的浏览器退回 `100vh`，读不到 `env()` 时安全区按 `0px` 处理，布局不会坏，只是少了留白。
